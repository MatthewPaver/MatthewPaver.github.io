# Portfolio context

*Updated 28 July 2026*

## Purpose

This is Matthew Paver's personal software portfolio. It helps a hiring manager,
collaborator or developer see what Matthew has built, open a working demo and
inspect the source.

The site is not a marketplace. The projects cover several fields, so the
homepage should not pretend they belong to one product suite.

## Homepage

Lead with Matthew's name and a short first-person introduction. Show three
projects first:

1. ProjectLens
2. MeetingProof
3. Output Gate

Keep DecisionGraph, Marketing ML Lakehouse, Paper Trading, House Hunter and
Happening in the project archive.

## Writing

Use plain, literal descriptions:

- name the material someone starts with;
- say what the tool does;
- mention the result only when it is visible in the demo.

Write in first person when Matthew is the subject. Keep project descriptions to
one or two sentences. Prefer “made-up data” and “sample data” to abstract
assurance language.

Avoid slogans, process manifestos, category theatre and repeated calls to
action. Do not use “flagship”, “ecosystem”, “journey”, “evidence-led”,
“seamless”, “frontier” or “revolutionary” in visitor-facing copy.

## Claims

- Every homepage entry must point to a public repository.
- Demos may use public or made-up data and must say so.
- Do not invent user numbers, ratings, testimonials or performance claims.
- Keep known limits on each project page.
- Do not list private repositories.

## Visual direction

Reuse the useful parts of the earlier product shelf: warm paper, Newsreader
headings, Manrope body text and large screenshots. Use the current screenshots
because they show the actual applications.

The page should feel like one person showing their work. Avoid marketplace
filters, app-store badges, animated marketing blocks and decorative AI imagery.
